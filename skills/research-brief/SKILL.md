# 深度调研简报

## 适用场景

用户要求「调研 / 分析 / 对比 / 了解一下」某个主题，并希望得到可读的结构化结论时使用。

## 工作流程

1. **拆题**：把主题拆成 3–5 个必须回答的子问题，先在心里列出来（可以写进回答里）。
2. **取证**：对每个子问题调用 `http_get` 抓取 1–2 个权威来源（官网、文档、论文、政府/机构页面）。不要只抓一个来源就下结论。
3. **交叉验证**：数字、日期、版本号这类硬信息，至少要有两处独立来源；冲突时明确写出「来源 A 说 X，来源 B 说 Y」。
4. **成文**：按下面的结构输出。
5. **落地文件（可选）**：用户要求保存时，用 `write_file` 写到 `reports/<主题>-<日期>.md`。

## 输出结构

```
## 一句话结论
（30 字以内，给出判断而不是复述问题）

## 关键发现
1. …（每条一句话结论 + 支撑事实）
2. …
3. …

## 分维度分析
### 维度 A
…
### 维度 B
…

## 风险与不确定性
- 哪些结论证据较弱
- 哪些来源可能有时效性或立场偏差

## 来源
- 标题 — URL（访问日期）
```

## 写作要求

- 结论先行，先给判断再给论据。
- 每个关键数字后面标注来源序号，例如「（来源 2）」。
- 不确定就写「不确定」，不要编造数据或链接。
- 中文输出，术语保留英文原词。
