# 联网检索

## 适用场景

问题涉及**会变化的事实**时使用：最新新闻、价格、版本号、政策条文、公司/人物近况、赛事比分、天气、文档里的具体参数、某个报错的最新解法。

纯常识、纯推理、纯代码结构问题不需要联网，直接回答，别浪费步骤。

## 三条铁律

1. **先搜后答**：时效性问题的结论必须落在具体 URL 上，不许凭记忆编版本号、日期、数字。
2. **不许编链接**：只使用 `web_search` / `http_get` 真实返回过的地址；没搜到就写「没找到可靠来源」。
3. **摘要 ≠ 原文**：搜索摘要只能用来筛候选，关键数字和引文必须用 `http_get` 打开原文确认。

## 步骤

1. **拆查询**：把问题拆成 1–3 个查询串，用关键词而不是整句话。
   - 中文问题先搜中文；技术/国际话题补一条英文查询。
   - 需要近期信息时把年份写进去，例如 `2026 个税专项附加扣除 标准`。
   - 想限定站点用 `site` 参数（如 `site: "docs.python.org"`），不要手写 `site:` 到 query 里更重要——两种都行，参数更稳。
2. **搜**：`web_search`（默认 6 条，可调 `max_results`）。

   ```json
   {"query": "个税专项附加扣除 2026 标准", "max_results": 6}
   ```

   多条查询可以一次发多个 `web_search` 调用，不必等前一条结果。
3. **选源**：官方/一手（官网、文档、公告、法条）> 权威媒体 > 垂直社区 > 论坛问答。同一事实尽量找 2 个独立来源；只有 1 个来源时在答案里注明。
4. **读原文**：对挑中的 1–3 条用 `http_get` 抓正文，`max_chars` 可以给 8000–15000。
   - 页面较长、来源较多（≥4 条）时，改用 `run_skill_script` 批量存证，再挑文件读：

     ```json
     {"skill": "web-search", "script": "fetch_pages.py", "args": ["https://a.com/x", "https://b.com/y"]}
     ```

     脚本会把正文存到 `web-cache/<时间戳>/`，打印标题、字数、路径和前 200 字。
5. **对账**：数字、日期、版本号逐条比对。冲突时不要挑一个装作没有分歧，直接写「A 说 X（来源 1），B 说 Y（来源 2）」并说明哪个更可信（官方/更新更近）。
6. **成文**：按下面的模板输出，最后给来源清单。
7. **落盘（可选）**：用户要求保存时用 `write_file` 写到 `notes/<主题>-<日期>.md`。

## 打不开怎么办

| 情况 | 处理 |
| --- | --- |
| `HTTP 403` / 需要登录 | 换一个来源，或退回用该条的搜索摘要，并在答案里标「未读到原文，据搜索摘要」 |
| 页面只有导航没有正文（JS 渲染） | 换同主题的静态站点/文档站，或用 `run_python` 抓它的 API/JSON 接口 |
| 搜索 0 条结果 | 缩短关键词、去掉引号、换英文再搜一次 |
| 中文页面乱码 | 已自动处理 utf-8/gb18030；还乱就换来源 |
| 内容付费墙 | 找转载/官方摘要，注明未获取全文 |

## 输出模板

```
## 结论
（先给答案，1–3 句，含关键数字和日期）

## 依据
1. …（事实 + 来源序号）
2. …

## 需要注意
- 时效性：信息截至 YYYY-MM-DD
- 分歧/不确定：…

## 来源
1. 标题 — URL（访问日期 YYYY-MM-DD）
```

## 自检清单

- [ ] 每个关键数字/日期都能对到某条来源
- [ ] 所有 URL 都是工具真实返回的，且可点开
- [ ] 时效性强的结论写了「截至某日」
- [ ] 没读到原文的地方明确标注了
- [ ] 没说「根据我的了解」，而是「根据来源 N」
