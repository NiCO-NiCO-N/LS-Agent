# 代码审查

## 适用场景

用户给出文件路径、仓库位置或代码片段，要求 review、找 bug、评估质量时使用。

## 步骤

1. 用 `list_dir` 了解目录结构，再用 `read_file` 读取目标文件（大文件分段读）。
2. 必要时用 `run_python` 做静态检查（例如统计复杂度、跑 `ast.parse` 验证语法）。
3. 按下面的严重程度分级输出问题，每条都要给出**文件:行号**和**可直接替换的代码**。

## 输出结构

```
## 结论
（可以合并 / 需要修改 / 建议重写，一句话）

## 严重问题（会导致错误或安全问题）
- [文件:行] 问题描述 → 建议

## 一般问题（可维护性、性能）
- …

## 小建议（命名、格式）
- …

## 修改后的关键代码
```python
…
```
```

## 审查清单

- 边界条件：空值、空列表、超长输入、并发
- 错误处理：异常是否被吞掉、资源是否释放
- 安全：命令注入、路径穿越、密钥硬编码
- 性能：循环内 IO、重复计算、N+1
- 可读性：命名、函数长度、重复代码

## 约束

- 不要为了凑数而提无关紧要的问题；没有问题就说没有问题。
- 不要重写整个文件，除非用户明确要求。
