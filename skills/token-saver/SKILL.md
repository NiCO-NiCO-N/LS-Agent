# 省 Token 执行守则

## 一句话原理

**一次对话的总花费 ≈ 步数 × 每步重发的上下文长度。**

模型没有记忆，每一步都要把「系统提示词 + 全部历史 + 全部工具 schema」重新发一遍。
所以省 token 只有两个抓手：**少走几步**，**让每一步重发的东西更短**。少写字只是第三位。

## 钱花在哪

| 组成 | 每步都重发？ | 谁在控制它 |
| --- | --- | --- |
| 系统提示词 | 是 | 启用技能数量、`always: true` 的技能正文 |
| 历史消息（含工具结果） | 是 | 会话长度、单条工具结果体积 |
| 工具 schema | 是 | `disabled_tools` |
| 本次生成的回答 | 否 | `max_tokens` |

工具结果一旦进入历史就**永久计费**：第 1 步塞进去 8000 字，第 5 步还在为它付一次钱。
所以最贵的错误是「把整个文件/整篇网页读进上下文」。

## 六条硬规则

1. **先规划再动手**：动手前用两三句定下「要读哪个文件、读哪几段、跑什么脚本」，一次做完。
   禁止「先读一点看看 → 再读一点看看」的试探式操作，每试探一次就是一次全量重发。
2. **只读需要的那一片**：文件默认别整篇读；先 `max_bytes: 3000~4000` 看结构，定位到行号再用 `offset` 精读。
3. **一次脚本代替多轮工具**：三次「读文件 + 计算」的循环，改成一个 `run_python`。
   把中间结果留在脚本变量里，只在 stdout 打结论（stdout 只保留前 6000 字符）。
4. **大结果落盘，上下文只留摘要**：超过约 2000 字的产出（正文、表格、报告）用 `write_file` 写到工作区，
   对用户只说「写了哪里 + 3 行要点」。不要把全文再复制到回答里。
5. **不重复、不死磕**：同一工具同一参数只调一次；连续两次失败必须换策略（换参数、换来源、换工具），
   不要第三次重试同一条路。
6. **输出收敛**：默认 10~15 行，结论先行。用户明确要长文时才展开，并优先产出文件而不是聊天长文。

## 工具预算表

| 工具 | 默认消耗 | 省法 |
| --- | --- | --- |
| `read_file` | 默认 20000 字节 ≈ 5–7k token | 先 3000–4000 字节探路，`offset` + `max_bytes` 精读 |
| `http_get` | 默认 6000 字符，上限 20000 | 4000 起；只要某个参数/版本号就别抓全文 |
| `web_search` | 每条结果带摘要 | 一次调用多给几个 `query`，`max_results` 6 够用，别反复搜同义词 |
| `run_python` | stdout 6000 / stderr 3000 | 一次跑完，只 print 结论，别 print 中间大表 |
| `list_dir` | 最多 200 项 | 用 `pattern` 过滤，别列全盘 |
| `load_skill` | 一个技能全文 | 只在与任务确实对口时加载；加载过就别重复加载，同技能内不用再读第二遍 |
| `run_skill_script` | 输出即结论 | 技能已封装好流程时优先用它，别手搓一串多步调用 |

## 阶梯读法（最常省下钱的地方）

**第 1 步 概览**：只读开头看结构。

```json
{"path": "app/agent.py", "max_bytes": 2000}
```

**第 2 步 定位**：用搜索或脚本找行号，不要顺序读。

```json
{"code": "import re,sys\nfor i,l in enumerate(open('app/agent.py',encoding='utf-8'),1):\n    if 'tool' in l: print(i, l.rstrip()[:100])", "timeout": 20}
```

**第 3 步 精读**：只读命中段前后。

```json
{"path": "app/agent.py", "offset": 18000, "max_bytes": 3000}
```

三条路都走完通常 1/5 于整篇读的成本，而且更准。

## 上下文卫生

- 长文档、长日志、长 JSON **不要**贴进对话；先落盘或让脚本筛，再只引用行号与关键几行。
- 一个文件读第二次之前先问：上次的结论还在吗？在就直接用。
- 错误信息只保留「类型 + 关键一行 + 位置」，不要把整段 traceback 反复搬来搬去。
- 多轮探索用 `write_file` 记一个 `notes/scratch.md` 当外部记忆，可以让会话重新开始而不丢进度。

## 审计成本（附带脚本）

任务开始前或怀疑太贵时，先量一下：

```json
{"skill": "token-saver", "script": "budget.py", "args": ["app/agent.py", "README.md"]}
```

输出每个文件的字节数、字符数、中文占比、估算 token，以及建议的读法（直读 / 分段 / 只脚本检索），并给总预算。
路径按「工作目录 → 项目根 → workspace」顺序解析，写相对路径即可。

看当前会话有多贵、谁最占地方：

```json
{"skill": "token-saver", "script": "budget.py", "args": ["--session", "65879c761ae1"]}
```

它会列出总 token、每条消息的占比和前 5 个最贵的条目，并提醒「每多一步就要再付一次这份历史」。

## 自检清单

- [ ] 这轮用了 ≤ 4 步就给出结果了吗？
- [ ] 有没有把 > 4000 字符的原文塞进上下文？
- [ ] 有没有重复读同一文件 / 重复搜同一件事？
- [ ] 长产出是否已落盘，回答里只留了路径 + 要点？
- [ ] 最终回答是否在 15 行内（用户没要求长文时）？

## 给开发者看的三条工程改进

技能只能约束行为，真正的大头在运行时：

1. **历史窗口 + 摘要**：目前每步重发整个会话，长会话成本是平方级。加「保留最近 N 轮 + 早期对话压成一句摘要」收益最大。
2. **`always: true` 技能要克制**：它的全文会进每一轮系统提示词，一个 3k 字的 always 技能等于永久加价。
3. **工具结果分层**：给模型看摘要、给磁盘留全文，按需再取；比单纯截断更省也更准。
